# Pilot Evaluation Plan (30 queries)

Purpose
- Run a small, repeatable 30-query pilot comparing SAGE Graph RAG vs Traditional RAG.

Scope
- Pilot size: 30 queries (sampled or provided in `data/eval/qa_pairs.json`).
- Compare outputs from two systems across automatic metrics and grounding checks.

Protocol (concise)
1. Prepare a QA set of 30 QA pairs: each item is a JSON object with keys: `question`, optional `reference`, optional `gold_evidence`.
2. For each QA pair, run both systems (SAGEGraphRAG, TraditionalRAG) with the same LLM+embedding configuration.
3. Capture the following from each system: `answer` (string), `thinking` (list/string), `context` (structured), `latency` (seconds).
4. Evaluate:
   - Automatic overlap: ROUGE-L (precision/recall/f1) between answers and optional `reference`.
   - Similarity between system answers (ROUGE-L when no reference).
   - LLM-based judgment (if evaluation LLM configured) returning scores and rationale.
   - Grounding checks: for any `gold_evidence.cypher_paths` run each path against Neo4j; mark if evidence exists.
5. Persist per-query detailed results and overall artifacts (CSV, PNGs) to `results/`.

Query families (for coverage)
- Factual single-hop retrieval (explicit doc field answers)
- Multi-hop inference (requires graph traversal)
- Person/role lookup (who/what responsibilities)
- Timeline/deadline extraction
- Project/status/ownership questions
- Ambiguous/unanswerable questions (to test abstentions)

Gold-evidence format
- QA pair example:
  {
    "question": "Who is responsible for data analysis?",
    "reference": "Bob Smith is responsible for data analysis.",
    "gold_evidence": {
      "cypher_paths": [
        "MATCH (p:Person)-[:WORKS_ON]->(t:Task) WHERE t.name CONTAINS 'data analysis' RETURN p.id LIMIT 1"
      ]
    }
  }

Metrics
- ROUGE-L precision/recall/F1 against reference when available.
- ROUGE-L similarity between system answers (no reference).
- LLM evaluation: 1-10 scores and preferred system.
- Latency per system (mean/median/std).
- Grounding coverage: fraction of cypher evidence paths that exist.

Deliverables
- `results/pilot_results.json` containing per-query full records.
- Summaries and plots generated by the harness (`results/*.png`, `results/*.csv`).

Evaluation steps (executable)
1. Ensure Neo4j and API keys are available (NEO4J_URI, NEO4J_USERNAME, NEO4J_PASSWORD, NEO4J_DATABASE optional, GROQ_API_KEY).
2. Place QA pairs in `data/eval/qa_pairs.json` (or let harness use its defaults).
3. Run the harness: `python scripts/run_pilot_harness.py --output results/pilot_results.json`.
4. Review `results/pilot_results.json` and generated visualizations.

Notes
- Use `--mock` to run offline smoke tests with deterministic outputs.
- Keep dataset small and document sampling strategy for reproducibility.
